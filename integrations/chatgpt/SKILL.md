# AllForOne workbench

Pick the reference that fits the user's deliverable. In a plugin, open it from `references/`. In a ChatGPT Project, look for the same filename among the project sources.

| Task | Reference | Result |
| --- | --- | --- |
| Plan an engineering change | `disciplined_software_engineering_framework.md` | Define the behavior change, dependencies, acceptance criteria, and verification steps. |
| Review a UI flow | `software_qa_and_testing_discipline.md` | Describe the initial state, the action, and the expected change for each test. |
| Evaluate an app idea | `app_opportunity_lab_playbook.md` | Identify the user, their current workaround, and a small experiment that could change the product decision. |
| Edit a technical draft | `human_writing_and_technical_prose.md` | Preserve technical facts and the author's intent while making the wording concrete. |

Work from the user's supplied materials. When a reference informs a recommendation, give its filename and section. For testing requests, distinguish checks actually run from checks the user can run. Use evidence the current chat can access.
